# 架构说明

## 为什么不是「让 AI 直接点网页」

直接让 AI 操作浏览器页面有三个老问题：

1. **把「没看清」当「没有」**——页面没加载完就断言「没有这个链接」
2. **把「被拦住」当「失败了再试一次」**——遇到验证码或拒绝页，疯狂重试，触发反爬
3. **没有纪律**——想点就点，想下就下，没有额度概念，把机构账号搞进黑名单

所以这个框架的核心是：**把人和机器的边界画清楚，让代码守边界，不靠自觉**。

## 三层结构

```
你（人）                   脚本（机器）
  │                            │
  │  登录 / 验证码 / 人工判断   │  检索 / 下载 / 归档 / 校验
  ▼                            ▼
┌─────────────────────────────────────────────┐
│             SUFE Research Harness           │
│                                             │
│  CLI 命令层 —— 结构化请求，JSON 输出        │
│  ─────────────────────────────────────────  │
│  额度记账层 —— 下载前先记账，检索限速       │
│  ─────────────────────────────────────────  │
│  适配器层 —— 每个数据库一个适配器          │
│  ─────────────────────────────────────────  │
│  浏览器端口层 —— 只发类型化命令给 Chrome   │
│  ─────────────────────────────────────────  │
│  校验层 —— 身份锁定、SHA-256、manifest     │
│                                             │
│  专用 Research Chrome（你登录过的会话）     │
└─────────────────────────────────────────────┘
```

## 关键设计

### 1. 人工闸门

遇到以下情况，脚本必须停下，把控制权交还给你，**不能继续往下走**：

- 登录页（WebVPN、知网个人账号）
- 验证码（滑块、拼图、短信）
- 出版商的拒绝页、付费墙
- 无法判断当前页面状态时

判断「该不该停」的逻辑写死在代码里，不是靠脚本自己觉得。

### 2. 写前记账

下载之前先落账，这是防止「失败重试循环」的关键：

- 每天默认 15 篇（可调）
- 同一篇每天最多 2 次（防死循环，不可调）
- 下载间隔至少 15 秒
- **先记账，再下载**——中途失败也算数，不会因为「没成功」反复重试

### 3. 检索限速

- 两次检索间隔至少 20 秒
- 状态落盘，多个进程共享同一份限速记录
- 同一时间只有一个进程能驱动专用 Chrome（文件锁）

### 4. 不把「判断不了」报成结论

| 情况 | 不是 | 处理 |
|---|---|---|
| 无法判定全文权限 | 出版商拒绝 | 单独状态，停下 |
| 读不到页面 | 验证页消失了 | 重新观察，不硬下 |
| 零检索结果 | 撞到验证页 | 检查页面状态后再报 |

### 5. 身份锁定

- 检索结果和详情页核对 DOI / 标题
- 下载文件和目标论文核对
- 原始文件保留，算 SHA-256
- 生成 manifest，**不含任何密码、cookie、token**

### 6. 代码和数据分离

- 代码目录：只有代码、配置模板、文档
- Output Root（仓库外）：所有下载、运行记录、日志、论文库
- 代码目录里不出现任何学校数据

### 7. 专用 Research Chrome

- 独立 profile：`%USERPROFILE%\ResearchHarness\chrome-profile`
- 和日常浏览器完全隔离，不污染你平时的登录态
- 通过 CDP 附着操作，脚本不重复启动浏览器
- `--restore-last-session`：正常退出后登录态可恢复

## 为什么用 CDP 而不是另开浏览器

1. **登录态复用**——你在专用 Chrome 里登录一次，之后所有脚本操作都带着登录态
2. **不被检测**——操作发生在真实浏览器进程上，不是无头模拟器
3. **稳定**——不反复开新窗口，页面状态可追踪

## 参考

设计思路参考 [HUNNU Research Harness](https://github.com/)（湖南师范大学版科研助手）：
- 人在环路、人工闸门
- 写前记账的下载额度
- 跨进程检索限速
- 身份锁定与 SHA-256 留档
- 代码与数据分离

针对上财环境做了调整，主要是：

- 知网不走 WebVPN（学校包装地址有 bug），改个人账号直连
- 机构路由只针对上财的数据库导航
- 适配器只保留上财实际可用的来源
